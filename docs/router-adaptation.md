# 为自己的路由器适配

离网自动化把路由器的**实时在线终端列表**作为规则引擎的输入。判断兼容性前，先记下设备的品牌、完整型号和固件版本。相同的管理页面外观并不能保证接口一致。

## 当前实现

应用接受私有 IPv4 地址，以 HTTP 默认端口连接。内置客户端使用锐捷 eWeb 管理账户 `admin`，从登录页读取该固件使用的登录参数，登录后通过 `devSta.get` 的 `user_list` 查询在线终端。若界面报「未提供可识别的登录加密参数」或「未返回有效的实时设备列表」，请先核对型号与固件支持的接口。[客户端实现](../server/router.mjs)

## 接入另一个型号

1. **找到实时数据源。** 优先选择厂商提供的只读接口。在自己的设备上对照管理页面和接口结果，分别核对终端上线、断开 Wi-Fi、有线拔线后的表现。DHCP 租约和历史终端可能在设备离开后保留很久，直接拿它们判断在线会错过离线事件。
2. **实现读取约定。** 参照 `RouterClient.listDevices()`，返回一个 Promise，成功时给出本次在线设备数组。统一 MAC 格式并去重。查询超时、认证失败、响应格式异常都应抛出错误，只有成功确认没有在线终端时才返回空数组。
3. **映射字段。** 下表列出界面和规则使用的字段。保留路由器原本提供的数据，可选字段缺失时使用下表的空值。接入新的认证方式、HTTPS、自定义端口或用户名时，同时调整连接设置、后端校验和凭据保存逻辑。[设置校验](../server/settings.mjs) · [连接界面](../src/App.jsx)
4. **接入并验证。** 服务端会在启动和保存连接设置时创建客户端，两个入口都要接入新实现。多型号并存时保存适配器选择，让现有配置默认沿用锐捷客户端。[服务端入口](../server/index.mjs)

| 字段 | 约定 |
| --- | --- |
| `mac` | 设备唯一标识。可复用 `normalizeMac` 转成大写冒号分隔格式。 |
| `name`、`alias` | 显示名称优先用用户备注，其次用主机名。无备注时 `alias` 为空字符串，无名称可显示「未命名设备」。 |
| `ip`、`os` | 可用时提供 IPv4 和系统名称，缺失时用空字符串。 |
| `connection`、`rssi` | 使用 `wireless` 或 `wire` 标识已知连接方式。无线信号为负整数 dBm；有线、未知或未上报时 `rssi` 为 `null`。 |

## 怎样确认适配成功

| 场景 | 预期 |
| --- | --- |
| 主手机离网，备用手机始终在线 | 路由器更新列表并达到连续确认次数后，遗落提醒执行一次。 |
| 两台设备一起离网 | 「备用手机仍在线」条件不成立。 |
| 设备一直离线，在中途启动应用 | 先等待一次真实状态变化，不补发离线通知。 |
| 读取超时、会话过期或返回异常 | 重新认证或报告读取失败，规则不会把请求失败视为所有设备离线。 |

分享适配结果时，请注明型号、固件、验证过的场景，以及无线和有线字段是否齐全。复现数据建议手写一小段虚构样本，只保留字段名、类型和状态变化。
